## 📌 제 1 장. 개요 및 글로벌 5대 서비스 벤치마크 총람

### 1.1 배경 및 목적
AITIP 플랫폼은 단순히 온라인 음식 주문 중개에 머무는 웹 서비스가 아니며, **'현장 하드웨어 단말기(Smart CTI) + 전국 광역/지역 유통망 + 다중 결제자산(신용카드, 카드사 포인트, 지자체 지역화폐, 스테이블코인)'**이 결합된 하이브리드 온·오프라인 융합 플랫폼이다.

영세 상인을 착취하는 기존 배달 독점 플랫폼의 약탈적 광고(깃발 꽂기 등)와 과도한 중개 수수료 체계를 원천 배제하고, 전국 단위 가맹점과 지역 대리점이 함께 성장하는 지속 가능한 법인 생태계를 완성하기 위해, 본 설계서는 글로벌 1위 엔터프라이즈 플랫폼들의 검증된 백오피스 아키텍처를 계승하여 AITIP 마스터 관리자(Platform Master Admin)의 10대 핵심 관제 체계를 규격화한다.

### 2.1 계층별 권한 및 역할 정의
1. **광역 총판 (Master Distributor / 접두사 `dst_`)**:
   - 전국 17개 특별시/광역시/도 단위 독점 영업권 보유 법인
   - 산하 지역 대리점 계약 체결 및 권역 할당 권한
   - 본사로부터 하드웨어 단말기를 대량 수급하여 산하 대리점에 공급
   - 세무 증빙: 법인 간 거래 전자세금계산서 청구
2. **지역 대리점 (Local Agency / 접두사 `agn_`)**:
   - 226개 시/군/구 단위 및 단위농협 연계 현장 법인/개인사업자
   - 관할 지역 내 소상공인 치킨집, 식당, 마트 영업 및 하드웨어 현장 설치
   - 가맹점 장애 발생 시 1차 현장 A/S 출동 및 CTI 라인 점검
   - 세무 증빙: 사업소득세(3.0%) + 지방소득세(0.3%) = 총 3.3% 원천징수 대상
3. **현장 영업사원 (Field Sales Rep / 접두사 `fsr_`)**:
   - 대리점 소속의 상가 방문 매니저
   - 가맹점 신청서 접수, 사업자등록증 진위 대조, 메뉴판 사진 수집 및 단말기 시연
   - 가맹점 온보딩 완료 시 1회성 유치 수당 수령

### 2.2 주소 검색엔진과 영업 유통망 매핑 거버넌스 (Address-to-Agency Resolver)
1. **공공 주소 엔진과 사설 조직의 분리 철칙**:
   - 주소 검색엔진(행안부 법정동/도로명주소 API)은 순수 공공 행정구역 데이터에 종속되며, 주소 데이터베이스나 드롭다운 옵션 내에 사설 총판 및 대리점 명칭을 혼입하는 행위를 영구히 금지한다.
2. **순방향 주소-영업망 자동 도출 흐름**:
   - 사용자가 순수 행정구역(시·도 / 시·군·구 / 도로명)을 검색하거나 선택 ➔ 주소 엔진이 행정구역 법정코드(`M-11-650`: 서울 서초구)를 확정.
   - 확정된 행정코드에 따라 본사 계약망 테이블(`territory_agency_mappings`)을 자동 조회하여, **해당 관할구역의 [광역 총판: (주)에이티파트너스] 및 [지역 대리점: (주)서초네트웍스]가 시스템적으로 도출**되어 화면 배지 스트립으로 표출.
   - 하단 관제 원장(가맹점, 실시간 주문, 라이더)은 해당 관할 대리점으로 즉시 핀포인트 필터링 연동.
3. **공통 필터 바 초기화 및 조회 제어 규격**:
   - 필터 바 우측에 `[초기화]` 버튼과 `[조건 조회]` 버튼을 나란히 배치한다.
   - `[초기화]` 클릭 시 기준일자(당일), 시·도 전체(`ALL`), 시·군·구 전체(`ALL`)로 즉시 리셋되며 하단 스트립이 `[권역] 전국 17개 시·도 전역 | [본사 통합 관제 (HQ)]` 기본 상태로 즉시 원복되고 관제 테이블이 전체 목록으로 새로고침된다.

### 2.3 전사 계층형 UID(통계청 KSIC 결합) 및 $O(1)$ 핀포인트 조회
- 가맹점 UID: `STR-{시도2}-{시군구3}-{대리점2}-{통계청업종5}-{점포순번4}` (예: `STR-11-650-01-56162-0001`)
- 주문 UID: `ORD-{가맹점UID}-{영업일자6}-{전표순번4}` (예: `ORD-11-650-01-56162-0001-261113-0042`)
- 주문 ID에서 가맹점 UID를 직접 파싱하므로, 데이터베이스 풀스캔(Full Table Scan) 0%의 $O(1)$ 핀포인트 조회를 보장하며 5대 도메인 세무 정산(일반과세 10%, 하나로마트 복합정산, 경로당 보조금 회계 대사)을 자동 분개한다.

### 2.4 UI 거버넌스: 금연 프로젝트 규격 'UID 숨김' 체크박스 및 컬럼 토글
- 관제 화면에서는 전사06.md 제6장 및 금연 점검 프로젝트(check-smoking-zone)의 표준 테이블 구조에 따라 1열 전표번호(`A-42`), 2열 주문 식별자 전용 열(`col-order-uid`), 3열 판매 매장 등으로 컬럼을 정석 분리한다.
- 상단 컨트롤 바에 `<label><input type="checkbox" id="chkHideUid" /> UID 숨김</label>` 체크박스를 배치하여, 체크 시 식별자 컬럼 전체를 `display: none;`으로 숨기고 체크 해제 시 가로 1줄 전체 펼침 상태에서 순수 `<code>${id}</code>` 표준 규격으로 표출한다.
- 관리자 화면, 행정 서식, 테이블 헤더 및 스트립에서 무분별한 이모티콘 사용을 전면 배제하고 정갈한 행정 표준 텍스트 레이블을 적용한다.

## 제 3 장. 하드웨어 스마트 단말기 물류 및 생애주기 관제

AITIP CTI 스마트 단말기(Dual DAA + Dual DPDT + ESC/POS 프린터 일체형)의 분실, 유출, 부정 사용을 방지하고 전국 유통을 통제하기 위한 전주기 상태 머신 및 온보딩 프로토콜이다.

```
[1. FACTORY_STOCKED] ➔ [2. ASSIGNED_DISTRIBUTOR] ➔ [3. ALLOCATED_AGENCY] ➔ [4. INSTALLED_MERCHANT] ➔ [5. ONLINE_ACTIVE]
       본사 창고 입고             총판 출고 배정                  대리점 출고                가맹점 S/N-매장 1차 매핑        MQTT 부팅 핸드셰이크
                                                                                               │
                                                                                               ▼ (고장/해지 발생 시)
                                                                                  [6. RETURN_MAINTENANCE / RMA]
                                                                                             단말기 회수 및 수리
```

### 3.1 하드웨어 식별자 체계 및 실물 자산 원칙
1. **단말기 제조 시리얼 (보드 S/N)**:
   - 제조 공장 플래시 메모리(EEPROM)에 영구 각인되는 고유 일련번호 (예: `CTI-BRD-882910`).
   - 기기 외관 바닥면 라벨에 1D 바코드 및 QR코드로 인쇄되어, 본사 입고 및 대리점 출고 시 스캔의 주 식별자로 사용된다.
2. **하드웨어 물리 MAC 주소 (`mac_address`)**:
   - 이더넷/Wi-Fi 통신 칩 고유 주소 (예: `B8:27:EB:14:8A:21`).
   - 단말기 부팅 시 네트워크 인터페이스에서 자동 추출되며, 임의 변조가 원천 차단된다.
3. **관리자 화면 컬럼 정규화 규격**:
   - 내부 시스템 참조용 UUID(`dev_01...`)를 화면 전면에서 완전히 배제하고, 1열에 `단말기 시리얼 (S/N)`, 2열에 `하드웨어 MAC 주소`, 3열에 `설치 매핑 점포`를 독립 분리하여 직관적인 실물 자산 관리를 보장한다.
4. **단말기 CTI 하드웨어 상세 관제 모달 (Detail Modal)**:
   - 테이블 행 및 `[상세보기]` 버튼 클릭 시 금연 점검 프로젝트 규격의 정갈한 모달이 팝업되어 4대 핵심 진단 정보를 제공한다:
     ① 물리 하드웨어 식별: 제조 S/N, 물리 MAC 주소, ATECC608 보안 칩, Dual DAA/DPDT 컨트롤러.
     ② 설치 매핑 점포: 매장 상호명, 점포 계층 UID(`STR-...` / `MRT-...`), 관할 대리점, 소재지.
     ③ 실시간 네트워크 & MQTT: 통신 상태, 로컬 IP, LTE 모뎀 번호, MQTT 브로커, Heartbeat 주기.
     ④ POS 연동 & 펌웨어: 연동 POS사, 펌웨어 버전, 활성 파티션(A/B), 프린터 용지 상태.
     ⑤ 하단 MDM 원격 제어: `[원격 재부팅 신호 전송]`, `[OTA 펌웨어 재전송]`, `[닫기]`.

### 3.2 현장 설치 매핑 및 MQTT 온보딩(Provisioning) 프로토콜
단말기가 가맹점에 설치되고 온라인으로 자동 연동되는 흐름은 다음 3단계로 엄격히 통제된다:

1. **대리점 기사의 현장 1차 사전 매칭**:
   - 대리점 설치 기사는 가맹점 방문 시 기사용 모바일 웹에서 단말기 외관의 **S/N 바코드**를 스캔하고, 설치할 **가맹점 UID(`STR-11-650-01-56162-0001`)**를 선택하여 등록한다.
   - 서버 DB(`devices` 테이블)에는 `board_serial`과 `store_id`가 '설치 대기(PENDING_ACTIVATION)' 상태로 1차 바인딩된다.
2. **단말기 전원 인가 및 MQTT 부팅 핸드셰이크 (S/N + MAC 전송)**:
   - 기사가 단말기에 전원과 네트워크를 연결하면 임베디드 리눅스 OS가 부팅된다.
   - 단말기 내부 데몬(`aitip-hardware-daemon`)이 EEPROM의 **S/N**과 실제 네트워크 NIC의 **물리 MAC 주소**를 자체 리딩한다.
   - 본사 MQTT 브로커(포트 8883, MQTTS/TLS)로 접속하여 `aitip/provision/handshake` 토픽으로 다음 JSON 패킷을 전송한다:
     ```json
     {
       "board_serial": "CTI-BRD-882910",
       "mac_address": "B8:27:EB:14:8A:21",
       "firmware_version": "v2.4.1",
       "timestamp": 1794617165
     }
     ```
3. **본사 서버의 자동 승인 및 1:1 하드웨어 바인딩 (활성화)**:
   - 본사 서버는 들어온 `board_serial`로 사전 등록된 가맹점 매핑을 확인하고, 패킷의 `mac_address`를 DB에 확정 기록하여 기기 상태를 `ONLINE`(`is_online = 1`)으로 자동 승인한다.
   - 이후 단말기 전용 토픽(`aitip/device/{S/N}/command`)이 개설되어 실시간 주문 푸시 및 30초 생존 신호(Heartbeat) 통신이 개시된다.
4. **무단 이동 및 복제 차단 (보안 방어)**:
   - 단말기 하드웨어와 매장 정보가 1:1:1(`board_serial` = `mac_address` = `store_id`)로 강력히 바인딩되므로, 기기를 임의로 타 매장이나 외부에서 인터넷에 연결할 경우 MAC 주소 및 네트워크 불일치로 즉시 통신이 차단되고 도난 경보가 발생한다.

## 💳 제 4 장. 다중 자산 결제 & 통합 정산 엔진 (Multi-Asset Settlement Engine)

'수수료 0원'이라는 단정적·비현실적 표현을 전면 배제하고, 결제망 원가와 다중 자산(카드사 포인트, 지역화폐, 스테이블코인)의 유통 원리를 정밀하게 반영한 차세대 정산 엔진이다.

### 4.1 4대 결제수단별 정산 프로세스 및 원가 구조

```
========================================================================================================================
결제 자산 구분          승인/취소 통신망            정산 주기          원가 및 수수료 구조               세무 증빙 처리
========================================================================================================================
1. 신용/체크카드        PG사 VAN/간편결제 망        D+1 ~ D+2 영업일   영세 0.5% ~ 일반 1.5% 원천 차감   여신금융협회 매입 자료
2. 카드사 복합포인트    카드사 포인트 API 결제      D+1 ~ D+3 영업일   포인트 수수료 차감 후 현금 입금   신용카드 매출전표 합산
3. 지자체 지역화폐      서울페이/지역사랑상품권 API D+2 ~ D+3 영업일   지자체 지원 할인액 국고 정산      현금영수증 지출증빙 규격
4. 스테이블 코인(Web3)  Polygon/Solana 온체인 블록체인 실시간 (블록 컨펌) 온체인 가스비(네트워크 원가)     디지털자산 거래명세서/원화환전
========================================================================================================================
```

### 4.2 계층별 정산 수식 명세

#### 1) 가맹점(Merchant) 일일 정산 수식
```
[가맹점 일일 순지급액 (Net Payout)] =
      총 결제 매출액 (A: 상품 주문금액 + 고객부담 배달팁 + 매장 식사비)
    + 본사/지자체 프로모션 지원금 (B: 할인쿠폰 본사부담금 + 지자체 지역화폐 보조금)
    + 카드사 포인트 본사 보전금 (C)
    - 결제망 원천 실비 수수료 (D: PG사 신용카드 결제 실비 수수료)
    - 배달대행사 위탁 배달비 차감액 (E: 부릉/생각대로/바로고 호출 건수 × 건당 실비)
    - 고객 환불/취소 시 가맹점 귀책 차감액 (F: DOC-12 분쟁 판정 결과)
```

#### 2) 지역 대리점(Agency) 월간 수당 수식
```
[대리점 월간 실수령액 (Net Commission)] =
    [총 발생 수당 (Gross)] - [원천징수 세액 3.3%]

where 총 발생 수당 (Gross) =
      (신규 입점 가맹점 수 × 건당 설치 인센티브 [예: 50,000원])
    + (실시간 활성 단말기 수 × 월간 유지관리비 [예: 10,000원])
    + (관할 가맹점 총 결제 거래액 [GMV] × 대리점 마진 쉐어 요율 [예: 0.2%])

where 원천징수 세액 =
      Gross × 3.0% (사업소득세) + Gross × 0.3% (지방소득세)
```

#### 3) 광역 총판(Master Distributor) 월간 마진 수식
```
[총판 월간 세금계산서 청구액] =
    [총판 공급가액] + [부가가치세 10%]

where 총판 공급가액 =
      (산하 전체 대리점 총 결제 거래액 [GMV] × 총판 오버라이딩 요율 [예: 0.1%])
    + (단말기 출고 대수 × 하드웨어 도매 유통 마진 차익)
    + (분기별/월별 권역 목표 달성 인센티브)
```

## 🌐 제 6 장. 외부 연동 게이트웨이 허브 (Third-Party Integration Hub)

외부 서드파티 통신망과 API의 장애가 플랫폼 전체로 번지지 않도록 완충하고 실시간 헬스체크를 수행하는 중앙 연동 허브이다.

```
                                  [외부 연동 게이트웨이 허브 (Integration Hub)]
                                                        │
         ┌──────────────────┬───────────────────┼───────────────────┬──────────────────┐
         ▼                  ▼                   ▼                   ▼                  ▼
+------------------+ +------------------+ +-------------------+ +----------------+ +------------------+
| [PG/결제 게이트웨이| | [통신사 CTI 허브]  | | [메시징 게이트웨이] | |[배달대행사 API]  | | [AI 에이전트 허브] |
| - 토스페이먼츠    | | - SKB/KT/LGU+   | | - 카카오 비즈엠   | | - 부릉 (Vroong) | | - Gemini Live API|
| - NH농협 제로페이 | | - 0504 가상번호 | |   알림톡 템플릿   | | - 생각대로     | | - 통화음성 A2A   |

| - Web3 RPC 노드  | |   가상 COM 브릿지| |   (Failover)      | | - 할증요율 동기화| |   실시간 관제    |
+------------------+ +------------------+ +-------------------+ +----------------+ +------------------+
```

1. **서킷 브레이커 (Circuit Breaker)**:
   - 외부 API(배달대행사, 통신사, 알림톡)의 응답 지연이 3초를 초과하거나 5회 연속 5xx 에러 발생 시 즉시 우회(Fallback) 처리
2. **데드 레터 큐 (Dead Letter Queue / DLQ)**:
   - 네트워크 일시 단절로 실패한 웹훅 및 정산 트랜잭션을 최대 72시간 동안 보관하며, 지수 백오프(Exponential Backoff: 10초, 30초, 1분, 5분...) 알고리즘으로 자동 재시도

## 🔒 제 8 장. 엔터프라이즈 보안, RBAC 권한 분리 및 불변 감사 추적

### 8.1 5대 역할 기반 접근 제어 (RBAC)
1. **슈퍼 관리자 (Super Admin)**: 본사 최고 책임자. 전 메뉴 및 시스템 환경변수, 펌웨어 OTA 배포 승인 권한
2. **재무 감사관 (Financial Auditor)**: 다중 자산 정산 승인, PG 대사, 홈택스 세무 자료, 은행 펌뱅킹 이체 승인 권한
3. **광역 총판 관리자 (Distributor Admin)**: 산하 대리점 목록 조회, 권역 단말기 재고 배정, 총판 마진 계산서 조회
4. **지역 대리점 관리자 (Agency Admin)**: 관할 가맹점 온보딩 신청, 단말기 시리얼 등록, 대리점 3.3% 수당 명세서 조회
5. **CS 운영 상담원 (Support Specialist)**: 전국 주문 모니터링, DOC-12 분쟁 접수, 라이더 배차 현황 조회 (정산 및 시스템 설정 접근 불가)

### 8.2 불변 감사 추적 (Immutable Audit Trail)
모든 관리자 행위(가맹점 계좌번호 수정, 단말기 강제 릴리즈, 분쟁 환불금 승인 등)는 `audit_logs` 테이블에 변경 전/후 JSON 스냅샷과 함께 관리자 IP, 세션 ID, 타임스탬프를 암호화 해시(SHA-256) 체인으로 영구 기록한다.

## 🗄️ 제 9 장. 데이터베이스 스키마 확장안 (TypeID 엄격 준수)

기존 `schema_aitip_v01.sql`에 본 설계서의 3계층 유통망 및 다중 자산 정산 항목을 수용하기 위한 D1 SQLite 스키마 확장 정의이다.

```sql
-- ============================================================================
-- [DOC-18] 1. 광역 총판 (Master Distributors)
-- ============================================================================
CREATE TABLE master_distributors (
    id                 TEXT PRIMARY KEY
                       CONSTRAINT chk_dst_id CHECK (length(id) = 30 AND id GLOB 'dst_[0-7]*'),
    name               TEXT NOT NULL,
    biz_number         TEXT NOT NULL UNIQUE,
    rep_name           TEXT NOT NULL,
    phone              TEXT NOT NULL,
    territory_code     TEXT NOT NULL UNIQUE, -- 17개 시/도 행정표준코드 (예: '11' 서울, '41' 경기)
    territory_name     TEXT NOT NULL,
    overriding_rate    REAL NOT NULL DEFAULT 0.001, -- 0.1% 오버라이딩 지분율
    bank_name          TEXT NOT NULL,
    account_number     TEXT NOT NULL,
    account_holder     TEXT NOT NULL,
    status             TEXT NOT NULL DEFAULT 'ACTIVE' CHECK (status IN ('ACTIVE', 'SUSPENDED', 'TERMINATED')),
    created_at         INTEGER NOT NULL,
    updated_at         INTEGER NOT NULL
);

-- ============================================================================
-- [DOC-18] 2. 지역 대리점 (Local Agencies)
-- ============================================================================
CREATE TABLE local_agencies (
    id                 TEXT PRIMARY KEY
                       CONSTRAINT chk_agn_id CHECK (length(id) = 30 AND id GLOB 'agn_[0-7]*'),
    distributor_id     TEXT NOT NULL REFERENCES master_distributors(id),
    name               TEXT NOT NULL,
    biz_number         TEXT NOT NULL,
    rep_name           TEXT NOT NULL,
    phone              TEXT NOT NULL,
    region_code        TEXT NOT NULL UNIQUE, -- 226개 시/군/구 법정동 코드 (예: '11650' 서초구)
    region_name        TEXT NOT NULL,
    onboarding_bounty  INTEGER NOT NULL DEFAULT 50000, -- 신규 가맹점당 유치 수당 (50,000원)
    monthly_device_fee INTEGER NOT NULL DEFAULT 10000, -- 단말기당 월 유지보수비 (10,000원)
    gmv_share_rate     REAL NOT NULL DEFAULT 0.002,    -- 가맹점 거래액 마진 쉐어 (0.2%)
    tax_type           TEXT NOT NULL DEFAULT 'BUSINESS_3_3' CHECK (tax_type IN ('CORPORATE', 'BUSINESS_3_3')),
    bank_name          TEXT NOT NULL,
    account_number     TEXT NOT NULL,
    account_holder     TEXT NOT NULL,
    status             TEXT NOT NULL DEFAULT 'ACTIVE' CHECK (status IN ('ACTIVE', 'SUSPENDED', 'TERMINATED')),
    created_at         INTEGER NOT NULL,
    updated_at         INTEGER NOT NULL
);

-- ============================================================================
-- [DOC-18] 3. 다중 자산 결제 거래 원장 (Multi-Asset Transactions)
-- ============================================================================
CREATE TABLE multi_asset_transactions (
    id                 TEXT PRIMARY KEY
                       CONSTRAINT chk_mat_id CHECK (length(id) = 30 AND id GLOB 'mat_[0-7]*'),
    order_id           TEXT NOT NULL REFERENCES orders(id),
    asset_type         TEXT NOT NULL CHECK (asset_type IN ('CREDIT_CARD', 'CARD_POINT', 'LOCAL_CURRENCY', 'STABLECOIN')),
    currency_symbol    TEXT NOT NULL, -- 'KRW', 'SHINHAN_POINT', 'SEOUL_PAY', 'USDT'
    gross_amount       INTEGER NOT NULL, -- 원화 환산 승인액
    raw_asset_amount   REAL NOT NULL,    -- 원래 자산 수량 (예: 15.20 USDT, 5000 Point)
```

### 11.3 전국 규모 운영을 위한 3대 UI/데이터 원칙 (상용 D1 이식 필수 조건)
1. **Search-First + Server Pagination**: 주문·가맹점·포인트는 전체 배열 로드나 `<select>` 드롭다운 나열을 금지하고, 검색어(`ord_...`, `cust_...`, 매장명, 사업자번호) + 기간 + 권역 필터 기반 서버 페이징(`page`, `limit`)으로 조회한다.
2. **Exception-First (예외 우선 큐)**: 대시보드와 관제 화면은 정상 건 나열이 아니라 미접수 초과, 배차 지연, 단말기 오프라인, 대사 불일치, CS 미처리 건을 최상단 알림 큐로 노출한다.
3. **현행 구현 상태 vs 상용 갭(Gap) 명시 (2026-11-16 오후 기준)**:
   - **구현 완료 (로컬 `dev-server.mjs` + `admin_data.json` 영속화)**:
     - 5대 대항목 슈퍼관리자 IA (`index.html`, `system-policies.js` 통합 탭) 및 `dashboard.js` 예외 우선 큐(`exceptions`)
     - 단일 어드민 멀티테넌트 RBAC: `admin-api.js`(`ROLE_ALLOWED_VIEWS`, `x-admin-role`, `x-tenant-id`) + `admin-app.js`(`applyRbacMenuGating`) + `dev-server.mjs`(지역/제휴 역할 `403` 차단 및 총판·대리점 소속 매장 격리)
     - Zero-PII CS·환불·블랙리스트 Search-First + 서버 페이징 (`cs-refunds.js` `?q=&page=&limit=`) 및 Zero-PII 포인트 서버 원장 (`points-ledger.js`), 소비자 PWA IndexedDB(`zero-pii-idb.js` `cust_...`) + `/api/food/public-feed` 실연동
     - `HQ_DIRECT` 직영 + 4섹션 조직 계약 등록 모달(개인정보보호·Zero-PII·NDA·표준계약 4종 필수 검증) + 3대 제휴(`SALES_ALLY`, `SERVICE_ALLY`, `TECH_ALLY`)
     - 가맹점 영업 토글/온보딩 승인 실연동 (`merchants.js`, `onboarding.js`), 본사 역할 분리(`service-zones.js` 오픈 지역 & 긴급 배달 차단)
   - **상용 이식 및 후속 과제 (Gap)**:
     - (1) 프로모션 4자 통합(본사·제휴/영업조직·가맹점·PWA 쿠폰 중복 규칙 및 `applied_promotions` 부담금 분개) — 내일 작업 예정
     - (2) Cloudflare Workers + D1 실 DB 및 JWT 세션 인증 이식, 멀티매장 `orders.store_id` 라우팅(`?storeId=...`), 출금/지급 승인 큐(`payout_requests`) 및 리뷰 블라인드 승인 큐 연동.
