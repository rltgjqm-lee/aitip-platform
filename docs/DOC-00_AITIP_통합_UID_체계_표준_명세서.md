## 1. 개요 및 계층형 식별자 설계 철학

### 1.1 배경 및 문제의식 (과거의 한계 극복)
기존 무작위 난수 기반의 Base32 UUIDv7 단독 식별자 방식(`ord_01jcbk...`)은 분산 고유성은 보장하나, 식별자 자체에 비즈니스 권역이나 소속 가맹점, 업종 정보가 전혀 존재하지 않아 다음과 같은 심각한 실무적 결함을 야기했습니다:
1. **가맹점 추적 불가 및 전체 테이블 풀스캔(Full Table Scan) 낭비**: 주문 ID만 보고는 어느 시/도, 어느 대리점, 어느 매장의 주문인지 알 수 없어, 단 1건의 가맹점을 조회하기 위해 수백만 건의 데이터베이스 테이블을 풀스캔하거나 무거운 JOIN을 반복 수행해야 했습니다.
2. **5대 서비스 도메인 세무·정산 분개 불가**: 소상공인 외식업(일반과세 10%), 단위농협 하나로마트(농축수산 면세 0% + 생필품 과세 10%), 경로당 식자재(지자체 보조금 회계 대사)의 정산 기준이 완전히 다름에도 불구하고, 단일한 무작위 번호로 채번하여 자동 분개가 원천 불가능했습니다.
3. **주소 엔진과 사설 영업망의 혼동**: 주소 드롭다운 안에 사설 총판 및 대리점 명칭을 억지로 하드코딩하는 엉터리 필터링으로 인해 데이터 표준이 심각하게 왜곡되었습니다.

### 1.2 전사 8대 계층형 UID 아키텍처 원칙 (`전사06.md` 표준 승격)
AITIP 플랫폼은 `전사_다중_프로젝트_통합_플랫폼_표준_아키텍처_총람_v06.md`의 8대 계층형 고유 식별자 체계를 절대 원칙으로 채택하고, 여기에 **통계청 한국표준산업분류(KSIC-11) 5자리 법정 업종코드**를 결합하여 **$O(1)$ 핀포인트 조회**와 **세무 정산 자동 분개**를 완벽히 실현합니다.

│ 1. 시군구 (M)   │ M-{시도2자리}{시군구3자리}     │ M-11-650 (서울 서초구)       │

## 2. 전사 계층형 UID 상세 규격 (가맹점, 마트, 시설, 주문)

### 2.1 소상공인 일반 외식 가맹점 식별자 (`STR-`)
* **규격 형식**: `STR-{시도2자리}-{시군구3자리}-{대리점2자리}-{통계청업종5자리}-{점포순번4자리}`
* **실무 예시**: `STR-11-650-01-56162-0001`
  - `11`: 서울특별시 (시·도 법정코드)
  - `650`: 서초구 (시·군·구 법정코드)
  - `01`: 관할 지역 대리점 ((주)서초네트웍스)
  - `56162`: 통계청 KSIC-11 법정코드 (치킨 전문점)
  - `0001`: 해당 권역/업종 내 1호 점포 (바른치킨 서초본점)

### 2.2 단위농협 하나로마트 식별자 (`MRT-`)
* **규격 형식**: `MRT-{시도2자리}-{시군구3자리}-{대리점2자리}-{통계청업종5자리}-{마트순번4자리}`
* **실무 예시**: `MRT-11-650-01-47121-0001`
  - `47121`: 통계청 KSIC-11 법정코드 (기타 대형 종합 소매업 / 하나로마트 B2B 직배)
  - 점포: 서초농협 하나로마트 양재점

### 2.3 수요 복지시설 및 경로당 식별자 (`FAC-`)
* **규격 형식**: `FAC-{시도2자리}-{시군구3자리}-{대리점2자리}-{통계청업종5자리}-{시설순번4자리}`
* **실무 예시**: `FAC-11-650-01-87391-0001`
  - `87391`: 통계청 KSIC-11 법정코드 (노인 주거 및 복지시설 운영업 / 경로당, 복지센터)
  - 시설명: 서초구 양재1동 복지센터

### 2.4 실시간 전사 계층형 주문 식별자 (`ORD-`)
* **규격 형식**: `ORD-{가맹점/마트UID}-{영업일자6자리(YYMMDD)}-{당일전표순번4자리}`
* **실무 예시 (외식업 배달 주문)**: `ORD-11-650-01-56162-0001-261113-0042`
  - 식별자 앞부분만 읽어도 **서울 서초구(11-650) ➔ 서초네트웍스 대리점(01) ➔ 치킨 전문점(56162) ➔ 바른치킨 1호점(0001)**이 1밀리초 만에 즉시 특정됨.
  - 뒷부분 `261113-0042`: 2026년 11월 13일 당일 42번째 인입 전표 (`A-42`).
* **실무 예시 (하나로마트 경로당 직배 주문)**: `ORD-11-650-01-47121-0001-261113-0012`
  - 식별자 내 `47121` 업종코드로 인해 단위농협 하나로마트 직배 주문임이 즉시 특정됨.
  - 당일 12번째 전표 (`M-12`).

### 2.5 관제 스마트 단말기 장비 식별 규격 (`DEV-`)
* **규격 형식**: `DEV-{장비타입2자리}-{보드일련번호}`
* **실무 예시**: `DEV-CTI-882910` (실물 제조 S/N: `CTI-BRD-882910`)
* **자산 관리 원칙**:
  - 관리자 테이블 전면에는 기기 외관 바코드와 1:1 일치하는 **단말기 제조 시리얼번호(S/N)**를 1열 주 식별자로 표기하고, 통신칩 고유 주소인 **물리 MAC 주소**(`B8:27:EB:...`)를 2열에 독립 배치합니다.
  - 가맹점 설치 시 대리점 기사의 S/N 바코드 스캔 사전 매칭과 단말기 전원 인가 시의 MQTT 부팅 핸드셰이크를 통해 물리 MAC 주소 및 가맹점 점포 UID(`STR-...`)가 1:1:1로 강력히 바인딩됩니다.

## 3. $O(1)$ 핀포인트 조회(Point Lookup) 및 무결성 메커니즘

### 3.1 전체 테이블 풀스캔(Full Table Scan) 0% 실현
* 기존 무작위 UUIDv7 방식은 주문 1건의 가맹점을 찾기 위해 전체 테이블 풀스캔(`SELECT * FROM stores WHERE id = ?`)이 필요했으나,
* 계층형 식별자 체계에서는 **주문 ID 자체를 파싱하여 가맹점 식별자를 직접 추출(Direct Derivation)**하므로, 데이터베이스 스캔량이 **정확히 0%**가 되며 $O(1)$ 단일 건 인덱스 핀포인트 조회가 수행됩니다.

```javascript
// AITIP 단일 진실 공급원 API Layer 파싱 엔진
const parsed = adminApi.parseHierarchicalUid('ORD-11-650-01-56162-0001-261113-0042');
// ➔ sido: '11', sigungu: '650', agency: '01', ksic: '56162', seq: '0001'
// ➔ merchant_id: 'STR-11-650-01-56162-0001' 즉시 특정
```

## 5. 공공 주소 엔진과 사설 영업망 조직의 분리 및 순방향 매핑 거버넌스

### 5.1 데이터 분리 철칙 (절대 원칙)
1. **주소 검색엔진의 공공성 사수**:
   - 주소 검색엔진은 대한민국 행정안전부 법정 행정구역 및 도로명 주소 체계에 100% 종속됩니다.
   - 주소 검색엔진 데이터베이스나 드롭다운 옵션 안에 사설 법인명(총판, 대리점 이름)을 혼입하거나 하드코딩하는 엉터리 구현을 영구히 엄단합니다.
2. **순방향 매핑 파이프라인 (Address ➔ Territory ➔ Organization)**:
   - 사용자는 순수 행정구역(시·도, 시·군·구, 읍·면·동, 도로명)을 검색하거나 선택합니다.
   - 주소 엔진이 행정구역 코드(`M-11-650`: 서울 서초구)를 확정합니다.
   - 확정된 행정코드에 따라 본사 계약망 테이블(`territory_agency_mappings`)을 즉시 조회하여, **해당 구역의 [광역 총판: (주)에이티파트너스] 및 [지역 대리점: (주)서초네트웍스]가 시스템적으로 자동 도출**되어 화면에 배지로 표출됩니다.
   - 하단 운영 원장(가맹점, 주문, 라이더)은 해당 관할 대리점으로 즉시 핀포인트 필터링됩니다.

## 6. UI 거버넌스: 금연 프로젝트 규격 'UID 숨김' 체크박스 및 컬럼 토글 표준

전사 플랫폼 총람 v06(전사06.md) 제6장 디자인 표준 및 금연 점검 프로젝트(check-smoking-zone)의 검증된 테이블 아키텍처에 따라 다음 UI 거버넌스를 엄격히 준수합니다:

1. **상단 컨트롤 바 체크박스 표준**:
   - 테이블 상단 액션 영역에 `<label><input type="checkbox" id="chkHideUid" /> UID 숨김</label>` 체크박스를 배치합니다.
   - 불필요한 이모티콘 사용을 전면 배제하고 정갈한 텍스트로 구성합니다.

2. **독립 컬럼 분리 및 컬럼 단위 숨김(Column Toggle)**:
   - 1열에는 식별 전표번호(`A-42`)를 독립 배지로 표시합니다.
   - 2열에는 주문 식별자 전용 열(`<th class="col-order-uid">`, `<td class="col-order-uid"><code>...</code></td>`)을 배정합니다.
   - 'UID 숨김' 체크박스 선택 시, 식별자 컬럼 전체를 `display: none;`으로 감추어 판매 매장 및 주문 내역, 금액 등의 가독성을 극대화합니다.
   - 체크박스 해제 시, 37자리 전사 계층형 UID 전체가 가로 1줄(`white-space: nowrap`)로 당당하게 펼쳐지며 순수 `<code>${uid}</code>` 표준 규격으로 표출됩니다.

3. **이모티콘 전면 배제 (전사06.md 제6장 5절 표준 준수)**:
   - 공식 관리자 화면, 행정 서식, 테이블 헤더 및 스트립에서 무분별한 이모티콘 사용을 전면 배제하고 표준 텍스트 레이블(`[관할 행정코드]`, `[관할 총판]`, `[관할 대리점]`, `조건 조회`)을 적용합니다.

## 7. D1 RDBMS 내부 기본키(PK) TypeID 접두사 표준 매핑 규격

비즈니스 표출용 8대 계층형 식별자(`STR-`, `ORD-`, `MRT-`, `SET-`)와 함께, Cloudflare D1 RDBMS 테이블 내부 물리 기본키(Primary Key)는 K-정렬 분산 고유성을 보장하는 TypeID(Crockford Base32 26자리) 체계를 유지합니다:

| 엔터티 구분 | 접두사 | 총 길이 | 표준 규격 예시 ID | 설명 및 적용 테이블 |
| :--- | :---: | :---: | :--- | :--- |
| **통합 회원** | `usr_` | 30자 | `usr_01jcbk9v4e2x8m4v0k5a1b2c3d` | 소비자, 점주, 배달원, 대리점 담당자 |
