## 1. 하드웨어 아키텍처 개요 및 핵심 원칙

### 1.1 하이퍼로컬 식당 및 마트 CTI의 현실적 과제
골목식당과 하나로마트 현장은 일반 IT 오피스와 환경이 완전히 다릅니다:
1. **마감 시 멀티탭 강제 차단**: 식당 사장님들은 영업이 끝나면 카운터 밑 멀티탭 스위치를 일괄 차단하는 습관이 빈번합니다.
2. **전화 두절 불가(Zero-Downtime) 원칙**: 단말기 고장이나 정전으로 인해 식당 키폰 전화가 먹통이 되면 당일 영업에 치명적인 손실이 발생합니다.
3. **통신사 보안 환경의 다양성**: 통신사(KT, LGU+, SKB) 및 키폰 기종(모임스톤, 다산 등)에 따라 SIP REGISTER 등록 주기, TLS/SRTP 암호화 여부가 상이하므로 현장 PoC를 통한 단계적 검증이 필수적입니다.

### 1.2 3대 하드웨어 설계 원칙
* **원칙 1: Fail-Open 기계식 LAN 바이패스 릴레이 필수 탑재**:
  * 단말기에 정전이 발생하거나, 전원 코드가 뽑히거나, 보드가 다운되더라도 **즉시 물리적 접점(Normal-Closed)으로 LAN IN과 LAN OUT을 직결하여 일반 키폰 통화가 100% 정상 유지**되어야 합니다.
* **원칙 2: 헤드리스(Headless) 초경량 컨트롤러 구조**:
  * 단말기 본체에 무거운 Chromium 브라우저나 고비용 디스플레이를 내장하지 않고, **화면 없는 초경량 CTI/프린터/MQTT 게이트웨이**로 설계합니다.
  * 점주 주문 확인 화면은 저가형 안드로이드 태블릿(주방 거치) 또는 사장님 스마트폰 PWA로 분리하여 Wi-Fi/WSS로 연동합니다.
* **원칙 3: RTC 배터리 내장을 통한 TLS 시간 동기화 보장**:
  * 매일 전원이 차단되는 환경에서도 RTC 백업 배터리(CR1220)와 DS3231 칩셋을 통해 시계를 유지함으로써, 부팅 즉시 NTP 동기화 전이라도 클라우드 TLS 인증서 검증 오류를 방지합니다.

## 2. Fail-Open 기계식 LAN 바이패스 회로 설계

키폰과 인터넷 모뎀 사이에 직렬로 연결되는 단말기 특성상, 전원 공급 상태에 따라 신호 경로가 자동으로 전환되는 기계식 DPDT 통신 릴레이를 구성합니다.

```
┌────────────────────────────────────────────────────────────────────────┐
│               AITIP Fail-Open 기계식 LAN 바이패스 회로 개념도            │
└────────────────────────────────────────────────────────────────────────┘

 [상황 A : 정상 전원 공급 시 (Relay ENERGIZED)]
   인터넷 벽면/모뎀 ──(LAN IN)──▶ [PHY 1 (eth0)] ──▶ CPU SIP B2BUA
                                                       │ (가로채기/처리)
   식당 키폰 전화기 ──(LAN OUT)─◀ [PHY 2 (eth1)] ◀───┘

 [상황 B : 정전 / 멀티탭 차단 / 보드 고장 시 (Relay DE-ENERGIZED : Normal-Closed)]
   인터넷 벽면/모뎀 ──(LAN IN)──┐ (기계식 접점 직결)
                                ├──▶ 릴레이 NC 접점 ──▶ (LAN OUT) ──▶ 식당 키폰
   단말기 내부 회로 ─────────────┘ (완전 분리 / 전화 100% 정상 통화)
```

### 2.1 릴레이 소자 선정 및 신호선 결선
* **소자**: 초소형 고주파 통신용 릴레이 **Omron G6K-2F-Y (DC 5V)** 2개 (TX 쌍 1개, RX 쌍 1개)
* **동작 메커니즘**:
  * 단말기 5V 전원 인가 시: 릴레이 코일 여자(Energized) ➔ NO(Normal-Open) 접점 연결 ➔ 이더넷 신호가 내부 Dual PHY(V3s 내장 PHY + SPI/USB 외장 PHY)로 입력되어 SIP B2BUA 엔진 구동.
  * 단말기 전원 상실 시: 스프링 복원력으로 즉시 NC(Normal-Closed) 접점 복귀 ➔ 인터넷 모뎀의 TX/RX 4가닥 선이 키폰 전화기 포트로 물리적 다이렉트 직결.

## 4. SIP 인라인 가로채기 현실화 및 단계적 PoC 계획

과거 보고서의 "인바운드 INVITE는 비밀번호가 없어 100% 전국 호환 확정"이라는 서술은 기술적 과장이었으며, 통신사 인프라에 따라 제약이 발생할 수 있습니다.

### 4.1 발생 가능한 현장 리스크 및 검증 항목
1. **통신사 발신지 IP 검증 (Source IP Binding)**:
   * 통신사 인터넷전화 교환기(SBC)가 가맹점 키폰의 MAC 주소나 초기 DHCP 할당 IP만을 인가하는 경우, 중간 B2BUA 장비의 패킷이 드롭될 수 있습니다.
   * *대응 방안*: 단말기가 초기 부팅 시 키폰의 MAC 주소를 복제(MAC Cloning)하여 통신사 패킷을 완벽히 투명 프록시(Transparent Bridge) 모드로 중계.
2. **SIP TLS / SRTP 암호화 통화**:
   * 대형 프랜차이즈나 금융권 키폰의 경우 통화 신호가 암호화되어 있을 수 있습니다.
   * *대응 방안*: 이 경우 무리한 패킷 복호화를 시도하지 않고, 단말기 전면의 CPG 아날로그(RJ-11) 포트 또는 통신사 공식 착신전환 API(KT 비즈링/통화매니저) 연동으로 폴백(Fallback).
3. **법률 및 규정 준수 (통신비밀보호법)**:
   * 통화 내용을 무단 도청하거나 녹음하는 것은 불법이므로, **통화 녹음 기능은 기본 비활성화**하며 오직 "ARS 안내 음성 송출" 및 "고객의 버튼 누름(DTMF) 감지" 목적으로만 동작하도록 펌웨어를 제한합니다.
