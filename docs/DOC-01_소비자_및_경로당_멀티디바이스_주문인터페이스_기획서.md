## 2. [NextOrders & Hyperlocal 계승] 3단 모드 스위처 컴포넌트

일반 배달앱의 단순 배달/포장 2단 스위처를 확장하여, **AITIP 3대 비즈니스 모델을 한 화면에서 전환**할 수 있는 탭 스위처를 상단에 배치합니다:

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                      AITIP 3단 배송/공구 모드 전환 탭                           │
├───────────────────────┬─────────────────────────┬───────────────────────────────┤
│ [ 🛵 일반 식당 배달 ] │ [ 🍱 경로당 식자재 발주]│ [ 🛒 하나로마트 공동구매 ]    │
└───────────────────────┴─────────────────────────┴───────────────────────────────┘
```

1. **`[ 🛵 일반 식당 배달 ]` (B2C)**:
   * 가맹점(`str_`) 메뉴 선택 및 일반 배달/포장 주문.
   * `order_type = 'GENERAL'`, `buyer_facility_id IS NULL`.
2. **`[ 🍱 경로당 식자재 발주 ]` (B2B)**:
   * 경로당(`fac_`) 회장님/복지사용 하나로마트(`mrt_`) 대량 식자재 발주 인터페이스.
   * 지자체 보조금 복지카드 결제 지원, `order_type = 'FOOD_SUPPLY'`.
3. **`[ 🛒 하나로마트 공동구매 ]` (Group Order)**:
   * 면 단위 농촌 및 식품 사막화 지역 주민들의 생필품/신선식품 공동구매.
   * 8자리 초대코드 기반 장바구니 취합 및 배송비 분할.

## 3. [SwadKart 계승] 공동구매 장바구니 및 배송비 분할 엔진

### 3.1 8자리 초대코드 기반 참여
* 방장(경로당 총무 또는 이장님)이 공동구매 방을 개설하면 8자리 영문/숫자 초대코드(`inviteCode`)가 발급됩니다.
* 참여 주민들은 링크 클릭 또는 코드 입력을 통해 동일한 장바구니 세션에 입장하여 원하는 품목을 각자 담습니다.

### 3.2 배송비 비례 분할 및 최대 잔여법 (Largest Remainder Method)
균등 분할 시 발생하는 소액 주문자(예: 두부 1모 2,000원 구매)의 배송비 역차별을 방지하기 위해 **주문 금액 비례 분할**을 적용하며, 1원 단위 절사 오차는 **최대 잔여법**으로 정산합니다.

```typescript
// 최대 잔여법(Largest Remainder Method) 기반 배송비 정산 알고리즘
export function calculateDeliveryShares(members: { userId: string, subtotal: number }[], totalDeliveryFee: number) {
  const totalOrderValue = members.reduce((sum, m) => sum + m.subtotal, 0);
  if (totalOrderValue === 0) return members.map(m => ({ userId: m.userId, share: 0 }));

  let distributed = 0;
  const rawShares = members.map(m => {
    const raw = (m.subtotal / totalOrderValue) * totalDeliveryFee;
    const floorVal = Math.floor(raw);
    distributed += floorVal;
    return {
      userId: m.userId,
      floorVal,
      remainder: raw - floorVal
    };
  });

  // 남은 1원 단위 차액을 소수점 잔여가 큰 순서대로 1원씩 배분
  let diff = totalDeliveryFee - distributed;
  rawShares.sort((a, b) => b.remainder - a.remainder);

  for (let i = 0; i < diff; i++) {
    rawShares[i].floorVal += 1;
  }

  return rawShares.map(s => ({ userId: s.userId, feeShare: s.floorVal }));
}
```

## 4. [Hyperlocal Delivery 계승] 하단 고대비 플로팅 카트 바

* 어르신들이 장바구니 이동 버튼을 찾지 못해 이탈하는 현상을 줄이기 위해, 화면 하단에 **[ 🛒 담은 품목 N개 (18,000원) ➔ 주문하기 ]** 고대비 주황색 플로팅 바를 상시 배치합니다.
* 장바구니 담기 클릭 시 햅틱 진동(Vibration API) 및 시각적 애니메이션을 통해 담김 상태를 명확히 인지시킵니다.

## 5. 실무형 배송 납품 완료 증빙 구조

현실적으로 작동하기 어려운 구두 4자리 OTP를 배제하고, 현장 오퍼레이션에 최적화된 **2단계 사진/서명 증빙**을 적용합니다.

1. **배송 완료 사진 촬영**:
   * 라이더 또는 어르신 배송원이 목적지(경로당 현관 또는 문 앞)에 물품을 두고 사진을 촬영합니다.
   * 브라우저에서 압축(WebP 변환) 후 Cloudflare R2 비공개 객체(`proofs/dlv_.../photo.webp`)로 업로드합니다.
2. **인수자 서명 (경로당/대면 시)**:
   * 대면 전달 시 수령인의 간이 전자서명을 캔버스로 입력받아 비공개 R2에 저장합니다.
3. **완료 전이**:
   * 서버 API(`POST /api/v1/deliveries/:id/complete`)는 JWT 토큰의 `workerId`와 일치 여부를 검증한 후 배송 상태를 `COMPLETED`로 변경합니다.
